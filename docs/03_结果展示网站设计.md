# 结果展示网站设计与开发指南

文档 ID：`result-viewer-design`；内容版本：`1.1.0`；日期：2026-09-20。依赖 [文档规范](01_系统文档规范与Agent协作.md) 的 PipelineDoc 1.0 和[全流程说明](02_全流程Pipeline说明.md)的模块/产物 ID；文档二 `1.1.0` 起主线/支线分组重排，本文信息架构同步。

本文原为设计方案；仓库内 `result_viewer/`（`backend/` + `frontend/`）已按本方案落地文档编译/热加载、运行绑定、统一 API、媒体服务与主要结果页，当前绑定运行样本为仓库内的 `movie_full_pipeline_20260912_v4`（§3.1 的信息架构即以它的真实产物为基准）。未完成部分见 §11 里程碑与交接说明。旧 `asset_viewer/` 保留为只读参考，不再扩展。

## 1. 产品目标与边界

网站应让读者快速回答：“这套系统做什么”“当前看到哪个步骤的结果”“输入来自哪里”“结果是否可信”“可以继续查看哪些证据”。至少包含系统介绍和流程结果两个一级模块；两者共用文档二中的模块名称、顺序、依赖及解释。

老板默认看到中文业务名称、流程位置、代表结果和有限的状态指标；开发者可以展开同一结果的字段、路径、原始 JSON、模型判断和失败原因。两者使用同一数据，不另建一套只显示成功样本的汇报页面。

一期做只读浏览、对比和溯源。模型执行、在线编辑结果、审核写回、任务调度、账户管理不纳入一期。页面上的“候选/已审核”读取现有证据，不提供会暗中改变业务产物的按钮。

### 可验收目标

| 目标 | 验收方式 |
|---|---|
| 文档即内容源 | 改文档二的介绍、模块名称或说明，服务与页面在目标时间内更新，无需重新构建前端 |
| 模块易增删 | 复用已有 adapter/renderer 新增模块，只改文档与必要运行绑定；禁用模块不删结果文件 |
| 说明与结果一致 | 任何结果页都能定位一个稳定模块 ID 和同版本说明 |
| 来源可解释 | 图片/音频/视频能定位到 run、scope 和来源产物；缺失来源明确提示 |
| 状态不误导 | 处理完成、归属覆盖、候选资格、审核批准分别呈现 |
| 保留服务器使用方式 | 一个服务器端口承接页面/API/媒体，通过平台既有代理前缀访问 |

性能目标是后续验收目标，不是本次实测：0912_v4 样本下，暖缓存首屏目标 2 秒内；普通分页 API p95 500ms 内（不含模型调用和媒体全量下载）；有效文档变更至页面可见目标 5 秒内；代表媒体按需加载。必须在注明服务器、样本大小、网络条件和缓存状态后报告实际结果。

## 2. 技术架构决策

建议 React + TypeScript + Vite 构建静态前端，FastAPI/Uvicorn 提供 Python 读取服务；服务器部署构建后的静态文件，与 API 和媒体同源。运行时不需要 Node 服务，不引入 SSR。Vite 的正式构建产物可静态托管，并可配置公共路径。[Vite 构建文档](https://vite.dev/guide/build)

选择理由：现有解析经验和产物处理代码在 Python 中，继续保留这一优势；前端拆组件后能独立维护画廊、时间轴、对比和通用说明。此项目的核心成本在多 schema/多布局适配和媒体溯源，初期不引入数据库、Redis、微服务或动态插件下载。

| 层 | 职责 | 输入 → 输出 |
|---|---|---|
| 文档读取器 | 解析/校验文档二，提取说明与模块定义 | Markdown → PipelineSpec + 内容树 |
| 运行目录注册表 | 管理可见运行、布局、外部来源绑定 | 运维配置 + 目录 → RunDescriptor |
| 产物定位器 | 解析产物 ID 的路径模板、检测歧义 | 产物契约 + run → ArtifactBinding |
| 数据适配器 | 读真实 schema，归一化实体/时间/状态 | JSON/JSONL/目录 → ResultEnvelope |
| 媒体与溯源服务 | 有边界地读取文件、支持 seek | 受控 media_id → 媒体字节 |
| 组件注册表 | 按 renderer 呈现标准结果 | 模块说明 + ResultEnvelope → 页面 |

```text
docs/02_全流程Pipeline说明.md ──→ 文档编译/校验 ──→ 不可变 PipelineSpec 快照
                                                                │
运维运行绑定 ──→ 目录/产物索引 ──→ 分 schema 的适配器 ──→ 统一结果 API
                        ↑                                       │
              服务器本地结果文件                                ↓
                                                     React 模块组件
本地媒体 ──→ 路径许可检查 + Range 响应 ──────────────────→ 播放/画廊
```

配置内容与运行数据独立更新。文档不携带实时 KPI，前端不维护第二套 STAGE_LABELS。编译后的 JSON 是文档二的派生缓存，不是需要人工双写的第二份配置文件。

导航由 groups、modules.order、view.enabled 和当前 route 生成，主线分组在前、"支线与历史兼容"始终排最末。高级开关显示 legacy/external/非路线模块，默认不把支线模块塞进首屏。用户仍可从系统介绍选择支线路线查看完整分支。

每个结果页固定四部分：业务标题与一句用途；流程位置及输入/输出跳转；该步骤的结果；说明/证据抽屉。模块说明来自文档二同模块六段正文，不能在前端复制改写另一版本。

### 3.3 系统介绍

首屏显示文档二 system.title/summary、overview 的业务解释、从依赖生成的分组流程图/树，以及当前路线。默认路线（`fixed-global-align`）的图只画主线模块；支线模块在选择 `legacy-chr`/`audio-evidence` 路线或展开全部后出现。图中的主路径、可选步骤、历史分支使用文字和线型区分，不能只靠颜色。

节点展示中文标题、用途和运行状态；点击进入对应结果模块。没有结果也能打开说明，提示“该运行未收录”或“尚未配置”。故事讲解顺序按 order，依赖线按 depends_on/optional_depends_on，不能把页面顺序当实际执行顺序。

不要求在网页复刻整个复杂图编辑器。一期用折叠树和小型依赖卡即可；当 DAG 的跨分支关系有必要时再增加图布局组件。

### 3.4 降低阅读难度

- 默认展示结果和结论，再展开算法细节；不在首屏铺满原始 JSON。
- 使用“全局片段”“人物轨迹归属”“角色声音候选”等文档名称，Stage 1.5/CHR/SPK 放技术详情和术语提示。
- global、shot、segment 同时出现时标注各自时间范围；时间控件明确“原片/全局片段/当前视频”。
- 空、未知、失败、未收录都显示可解释文字，禁止统一空白页面。
- 缩略图尺寸稳定、媒体懒加载；每次只自动播放用户选择的一个视频/音频，其他自动暂停。
- 全站保留当前 run/scope，在下游和上游间跳转时尽量保留选择；切换 scope 后清除已不适用 subject。

简明视图仍显示失败数、未知数和歧义标记。质量说明不会因为“给老板看”而被隐藏。

### 3.5 状态与指标

| 维度 | 例子 | 页面含义 |
|---|---|---|
| 执行 | succeeded/partial/failed/unknown | 这个处理过程是否完成，必须有证据 |
| 语义 | 已归属/unknown/new_subject_candidate | 身份是否已判断；候选集合不是角色 |
| 质量 | candidate/ambiguous/accepted/rejected/unreviewed | 素材能否被直接使用、是否经过审核 |
| 来源 | 当前运行/绑定外部来源/未收录/过期 | 与当前选择的运行关系 |

`running` 必须有明确的运行状态文件或活跃任务证据；文件正在变化不够。缺文件但无运行记录使用 `unknown` 或 `not_run` 的明确原因，不能推断模型失败。可见模块的产物绑定缺失用 `unconfigured`；路线不适用用 `not_applicable`。

每个指标对象包括 label/value/unit、分子/分母、粒度和解释。例如 `assigned_tracklets=91`、`all_tracklets=190`，计算归属覆盖率，名称中不能出现“准确率”。角色计数以 scope:S-ID 为单位；物体按候选和观测分别统计，125 行不等于 125 个物体；ASR 使用 global_id+asr_id 去重，不能把 global 和 segment 投影重复累加。

### 3.6 URL、筛选和无障碍

采用平台前缀下根页面的 query 路由，例如 `?tab=results&run=...&module=person_align&scope=global_0040&entity=...&view=compact`。页面导航使用浏览器 history，分享链接可恢复选择，减少深路径被平台代理错误回退的风险。

所有 query 由 URL API 编码；run/module/实体 ID 先验证，再读取。筛选项仅按模块 view.filters 渲染；无 subject 的模块不显示无意义人物框。搜索/分页/排序写入 query 时避免每次按键产生历史记录。

至少支持 1440px 桌面、1024px 平板；窄屏左侧导航改抽屉、对比卡改上下排列。标签、焦点样式、键盘操作、图片替代文本、音频文字/字幕入口和状态非颜色表达必须具备。

## 4. Renderer 与 Adapter 注册规范

Renderer 处理展示；Adapter 处理原始数据。相同 renderer 可服务多个 schema；不能把文件搜索、路径重映射、schema 猜测写在 React 组件中。

主线 renderer（顺序同文档二主线模块）：

| renderer | 对应模块 | 主要展示 |
|---|---|---|
| `source-overview` | source_prepare | 视频概览、处理区间 |
| `video-timeline` | shot_split/global_group/segment_plan/segment_export | 时间轴、视频、结构关系 |
| `transcript` | asr_timeline | 字幕列表、来源、时间定位 |
| `caption-detail` | global/shot/segment_describe | 视频与结构化描述、人物/物体引用 |
| `tracklet-gallery` | person_tracks | 带框视频、轨迹和观测画廊 |
| `alignment-evidence` | person_align | 归属、未知、证据及保留策略 |
| `audio-evidence` | voice_preview | 候选原声、对白与审核结论 |
| `character-gallery` | character_pack | 角色目录：裁图、候选声音与来源 |
| `record-table` | object_queue | 可筛选记录、关系和状态 |
| `object-evidence` | object_ground | 原图/框/mask/RGBA 与跨帧证据 |
| `scene-gallery` | scene_select | 主图/辅助图、版本对照 |
| `generation-bundle` | generation_bundle | 目标、参考、prompt、完整度 |
| `image-comparison` | i2i_review | 同条件多模型图片对比 |
| `audio-comparison` | tts_review | 参考声音和合成音频对比 |
| `artifact-browser` | result_browse | 限定目录的产物检索、分页预览 |

支线 renderer（仅"支线与历史兼容"分组使用，与主线共用组件注册表）：

| renderer | 对应模块 | 主要展示 |
|---|---|---|
| `audio-evidence` | voice_model | 前景/净语音、说话人建模证据 |
| `alignment-evidence` | legacy_refine | 逐镜头语义筛选、保留策略 |
| `identity-graph` | legacy_identity | CHR 成员、合并与冲突 |
| `character-gallery` | legacy_gallery/legacy_bind | 脸/身体/声音画廊、投票绑定 |
| `record-table` | compat_structure | 兼容 ClipRecord 记录检索 |
| `artifact-browser` | asset_demo | 历史演示产物检索 |

文档二为每个模块声明的 adapter 名称，是开发时必须注册的能力 ID。每个 adapter 提供 probe（轻量探测）、summary、list（分页）、detail、media_refs、provenance；输入为已解析的 ArtifactBinding，不接收客户端任意文件路径。

| 输入差异 | 适配器必须处理 |
|---|---|
| global/shot caption 的同名嵌套 | 按受支持 schema/结构解包，保留原始层级供审计 |
| segment_captions 一行是 global | 展开 segments，生成复合 segment 实体键 |
| 各处 shot ID 不同补零 | 转成规范 ID并保留 raw_id；不能跨 video 混合 |
| object V3/V4 | 分开映射执行状态和 ambiguous/cross-frame 质量证据 |
| 两种 review_status | 预览 valid/invalid 与审核 pending/approved 分别解释 |
| 新/旧 role_character | 新链候选复制和旧链批准参考使用不同 adapter，不假设相同准入 |
| 目录存在但格式不支持 | 返回局部 `unsupported_schema`，不能静默空列表 |

新增已有 renderer 的模块：在文档二增加完整模块与产物定义，配置运行绑定，校验通过后自动出现。新增文件 schema：新增 adapter、加入 schema fixture、注册后发布后端。新增交互：新增 renderer、注册并发布前端。后二者不能只改 Markdown 就凭空实现。

隐藏模块：设 enabled=false；重新计算导航，保持正在播放的媒体至用户切换或明确失效。废弃模块：lifecycle=deprecated，并保留说明和历史 deep-link 落点；需要物理删除时先调整 routes/依赖，校验引用，无任何业务数据删除操作。

## 5. 文档编译与热加载

### 5.1 编译流水线

固定文档路径来自服务器配置，不允许请求参数换任意 Markdown 路径。使用 CommonMark 解析器建立 AST/token 树，识别完整 fence info `json pipeline-system` 与 `json pipeline-module`，普通 JSON 示例不参与解析。

顺序：读取完整 UTF-8 文件 → JSON 严格解析 → 字段/类型/枚举校验 → 模块标记和六段标题校验 → ID、route、依赖、输入输出和 profile 交叉校验 → 无环检查 → adapter/renderer 能力检查 → 提取安全内容树 → 生成不可变快照。

解析器必须拒绝重复 JSON key、重复 ID、NaN/Infinity、未知协议主版本和悬空引用。字段默认拒绝未声明键；以后扩展放明确版本支持字段，不能静默接受拼错的 enabled。标题/顺序只以元数据为权威；Markdown 标题和元数据不一致时给出错误位置，避免人读和机读分叉。

只允许有限 Markdown 内容节点：段落、标题、列表、表格、代码示例、链接。HTML 注释只用作边界；其他原始 HTML 不执行。链接限制协议，模型文本和 JSON 全部转义；不启用 MDX、JavaScript 表达式或远程组件加载。

文档一规定的 paths/profile/schema 等字段要形成机器 schema 或等价类型校验；后续由同一协议定义产生验证/类型，避免 Python/TypeScript 各自改一套契约。第一版先准确实现约定，不在本次文档任务中创建代码。

### 5.2 热加载时序

```text
维护者保存文档二
    → 服务检测到文件版本变化（本地轮询；可选 watcher）
    → 防抖后读取完整内容并编译候选快照
    → 校验失败：保留旧快照，发布错误位置
    → 校验成功：一次性替换整个快照，产生新 doc_revision
    → 浏览器发现版本变化，获取新 spec
    → 更新说明/导航/布局；尽可能保留筛选、滚动和播放状态
```

一期采用可靠的轻量轮询：服务约每 2 秒检查文档元信息，变化后约 300ms 防抖并计算内容 SHA-256；浏览器约每 2 秒轮询版本接口，后台标签页降频。保存后内容稳定才编译；推荐文档编辑工具使用原子替换。可选 SSE 以后增加，不让平台长连接策略成为一期阻碍。

Vite HMR 只解决开发时前端代码更新，不能作为生产 Markdown 热加载机制。正式前端从 API 读取文档快照，不将文档二打包进 JS。

### 5.3 版本与一致性

| 标识 | 生成方式 | 用途 |
|---|---|---|
| `doc_revision` | 文档二原始完整内容 SHA-256 | 说明、导航、产物契约的一致版本 |
| `data_revision` | 运行相关 manifest 指纹/索引版本 | 数据列表和统计刷新；不是扫描所有媒体内容哈希 |
| `adapter_version` | 服务发布中的 adapter 版本 | 标识原始 schema 归一化规则 |
| `ui_build_id` | 前端构建版本 | 诊断组件能力匹配 |

spec/API 响应包含 doc_revision。前端请求数据时带期望版本；服务至少保留当前与上一可用快照供在途请求，已淘汰版本返回 409 `DOC_REVISION_EXPIRED` 并提示重新取 spec。不得把旧 adapter 路径结果与新说明原子外混合。

说明文字变更不必清掉媒体缓存或全量重扫数据；路径绑定/adapter/产物契约变化才使对应模块数据缓存失效。自动刷新不重置用户播放进度；实体确实被删除时显示“原结果已不可用”并保留当前位置提示。

### 5.4 损坏、回滚和首次启动

坏文档不取代最后可用快照；页面展示“新说明未生效，继续使用版本 …”，详情包含文件相对路径、行号、字段及原因，不回传服务器秘密路径。若没有任何可用版本，保留诊断外壳，spec 返回 503 `DOCUMENT_UNAVAILABLE`，不假装系统没有模块。

可将校验通过的派生快照保存至独立 `.viewer_cache/docs/<revision>.json`，服务重启时重新验证协议/能力后作为回退；此缓存可重建，不提交为权威配置。通过恢复上一版 Markdown 回滚，或者回退程序与其兼容文档版本；不要编辑缓存 JSON 形成第二份事实。

## 6. 运行绑定、数据契约与文件溯源

### 6.1 RunDescriptor 与配置

网站代码根、文档根、数据根分离。建议运维配置 `viewer.runtime.json`（未来新增配置文件，本次未创建），包含 listen、public_origin、base_path、workspace_root、allowed_runs、runs 的 layout_profile/source_roots/artifact_bindings。它只描述部署/路径，不复制模块中文名称或业务解释。

每个运行具有 `run_id/video_id/title/layout_profile/route_id/produced_code_revision/created_at`。不知道生产 commit/路线时使用 null/unknown，不用当前服务器 HEAD 填补。自动发现可作建议，但最终访问范围取 allowed_runs；不再限制目录必须叫 movie_full_pipeline_* 或必须有人物资产才能浏览。

custom 占位符按模块/产物绑定，不能全局只有一个 output。例如 person_tracks 的 tracklets 指向已核验源目录，voice_model 的 output 指向对应 global 声音建模根。多视频/多 global 的自定义输出可以按实体 scope 绑定；缺绑定返回 unconfigured，而非递归遍历磁盘碰运气。

### 6.2 ArtifactBinding

绑定至少包含 `artifact_id/run_id/profile/root_id/relative_path/source_run_id/producer_module_id/schema_hint/provenance_status`。整合样本从 0912/0912_v4 复用结果时保留 source_run_id 与原路径证据；网站不会把旧 JSON 内绝对路径改掉。

路径选择顺序：运维显式 artifact binding → profile 的唯一匹配路径 → 已登记来源的精确重映射。多份候选不一致返回 `AMBIGUOUS_ARTIFACT`。不能按 basename 全盘找同名文件，也不能把两个运行的 role_character 自动合并。

0912_v4 当前绑定（`result_viewer/viewer_config.json`，layout_profile=custom）：`shots/globals` → `middle/`，三级 caption → `captions_speaker/`，`segment_media` → `segments/segments.jsonl`（source_run=0912，路径重写映射回本运行），`voice_previews` → `voice_by_role_src/all_asr_manifest.jsonl`，`tracklets` → `assets/visual_person_v2/tracklets`，`role_binding`/`legacy_characters` → `characters/`（旧链产出，producer 如实标注）。person_align 的对齐详情（`assets/visual_person_v2/alignment/`）已具备目录，待补显式绑定后从"未配置"变为可看。

0916 接入时的处理：本地存在的 global_clips、characters、segments、scene、key_object 使用当前目录；middle/shot_clips 的源 run 媒体作为显式只读来源；tracklets 未收录时先显示缺失来源，需要查看时绑定 0912_v4 的对应根并核验 shot 集合/产物来源。纯靠人物对齐 summary 的 190 不能伪造本地 190 个 tracklet 详情。

### 6.3 统一返回结构

下面仅为接口形状示例，数字引用文档二静态样本；运行时由适配器计算：

```json
{
  "api_version": "1.0",
  "doc_revision": "sha256-of-markdown",
  "data_revision": "run-index-revision",
  "adapter_version": "global-alignment-v1.0",
  "run_id": "movie_full_pipeline_20260916",
  "module_id": "person_align",
  "status": {"execution":"succeeded","quality":"unreviewed","reason":null},
  "metrics": [
    {"id":"assigned","label":"已归属轨迹","value":91,"unit":"条","denominator":190,"scope":"selected-run","meaning":"归属覆盖，不表示准确率"}
  ],
  "items": [],
  "page": {"limit":50,"next_cursor":null,"total":190},
  "warnings": [],
  "provenance": {"artifact_ids":["direct_alignment"],"produced_code_revision":null}
}
```

Entity 至少包含 `key/title/status/media_refs/relations/fields/provenance`。key 使用文档一规定的复合对象；URL 可对对象编码为 opaque entity_id，不能用 `S1` 作为全站唯一键。`fields` 保存适配后的可展示数据，raw 只在详情按需取；不把 embedding/base64/全部长日志打进列表。

时间引用为 `{timebase, start_sec, end_sec, media_id, source_range}`；media_ref 为 `{media_id, kind, label, url, mime, duration_sec, thumbnail_url, availability}`。不返回由客户端直接拼接的任意 abs 路径。缺媒体有 missing/forbidden/unconfigured 状态，但其他字段仍可浏览。

关系示例：角色 → 归属行 → 轨迹 → OBS/crop → shot → global；物体 → candidate → shot 描述 → 定位帧 → reference set；声音 → ASR → candidate verdict → 可选 voice_link/审核。关系缺失时显示未知，不能推测成立。

### 6.4 增量索引与正在写入的结果

先索引小 manifest、summary、一级目录，不递归读所有图像。缓存键包含 run、module、binding、输入指纹和 adapter_version；按 mtime/size/inode 检测变化，相关文件变更才重新解析。必要时使用内容 hash 对可疑同名文件去重，避免为每次页面请求计算大型视频哈希。

JSONL 一行错误记录行号与部分可用数据；末尾半行/文件写入中可保留上一稳定版本并报告 partial。不能让读到空/半文件就替换所有成功结果。未来生产者建议临时文件+原子替换或完成标记，当前未具备时用稳定读取和重试处理，不能声称原子产物发布已存在。

分页默认 50、上限 200；大图/音视频使用媒体 URL，表格和画廊可虚拟滚动。目录浏览限定已注册产物根，限制深度、文件类型和数量；禁止把通用文件浏览做成整个服务器的目录列表。

## 7. 建议 API

所有端点相对 BASE_PATH，同源访问。GET 只读；无模型执行/写回接口。

| 端点 | 返回/用途 |
|---|---|
| `GET api/v1/version` | doc/data revision、当前有效快照、最近文档错误、ui 能力信息 |
| `GET api/v1/spec` | 系统元数据、模块目录、产物契约和安全正文；ETag=doc_revision |
| `GET api/v1/runs` | allowed_runs 的运行摘要；可用布局/来源状态 |
| `GET api/v1/runs/{run}/modules` | 每模块状态、计数、可用筛选；不含大 payload |
| `GET api/v1/runs/{run}/modules/{module}/items` | scope/subject/status/variant/cursor/limit 筛选后的分页实体 |
| `GET api/v1/runs/{run}/modules/{module}/items/{entity}` | 单实体详细结果和关系 |
| `GET api/v1/runs/{run}/artifacts/{artifact}/preview` | 受控产物片段；JSONL 行范围/上限，不能整文件无限返回 |
| `GET api/v1/runs/{run}/lineage/{entity}` | 有界上/下游溯源，默认一跳 |
| `GET media/{media_id}`、`HEAD media/{media_id}` | 媒体流、Range、内容长度/类型 |
| `GET healthz` | 进程健康、文档状态与数据根可达性摘要 |

错误结构统一 `{error:{code,message,request_id,module_id,artifact_id,location,retryable},doc_revision}`。示例 code：DOCUMENT_INVALID、UNSUPPORTED_PROTOCOL、UNREGISTERED_ADAPTER、AMBIGUOUS_ARTIFACT、UNSUPPORTED_SCHEMA、MEDIA_MISSING、DOC_REVISION_EXPIRED。区分 400 非法参数、404 未授权/不存在资源、409 版本过期/定位冲突、503 文档不可用；某个实体局部损坏通过 warnings/status 保留其余结果。

旧 URL/端点可保留一版只读兼容映射，转换 workspace/stage/scope/subject 到 run/module/entity。不得让新页面继续绕过适配层直接调用各旧解析分支；API 兼容与业务内部复用是不同层次。

## 8. 媒体、路径与本地结果读取

既要支持当前跨工作区复用，又要限定能读的文件。现有代码的词法检查允许 workspace 内软链接指向外部，README 对安全边界的描述不准确；新实现采用“登记来源根 + resolve 后范围检查”。

1. 后端从已注册 ArtifactBinding 生成 media_id，并绑定 run/产物/来源；客户端不能提交任意 abs 路径。
2. 先做路径规范化，再 resolve 软链接；最终目标必须位于该运行允许的 workspace/source_roots 中。
3. 显式允许 0912 镜头源目录等必要根，而非开放整个 `/gemini`、用户目录或仓库父目录。
4. 目标须为允许的普通媒体/文本文件；禁止读取设备、目录或外链任意 URL。text 预览也走同样边界。
5. 下载/打开时再次核验目标；对会被非受信主体修改的目录，使用文件描述符校验或只读挂载减小软链接替换竞态。

资源不可访问时返回局部原因，保留 caption/关系显示；不要在前端把原绝对路径拼进链接。日志记录受控相对定位、错误类型和 request_id，避免输出视频 base64、密钥和完整模型请求。

视频/音频必须支持 Range 请求、206、416、Content-Range、Accept-Ranges 和 HEAD，以便拖动进度。可基于 Starlette FileResponse 的现有文件响应能力实现，仍需前置 run/路径许可检查和所锁定版本的验证。[Starlette 文件响应](https://starlette.dev/responses/)

静态构建资源可使用内容哈希长缓存；文档/版本接口使用 revalidate/no-cache，媒体用私有缓存策略和适当 ETag，避免把内部结果默认标为公共共享缓存。内网身份依赖平台代理的前提需在部署时验证，不能因为能打开旧页面就假定所有端口都有相同授权。

## 9. 服务器部署与代理前缀

### 9.1 沿用的部署逻辑

```text
内网浏览器
    → 平台入口 <public_origin>/<base_path>/
    → Gemini 反向代理 / 路由与已有访问控制
    → 服务器/容器 0.0.0.0:<service_port>
    → 同一个 Python 服务：页面、静态资源、API、媒体
```

旧 README 示例监听 8910，并使用 `/gemini_web/asset_viewer/~58.59.115.26~31443~/<GEMINI_JOB_NAME>/` 的平台代理前缀。本次只核验源码和文档，没有探测该地址。新设计将 public_origin/base_path/port 设为部署配置，不把示例 IP、作业名或样本 run 编译进前端。

模块运行方式需从父目录启动以满足 package import；新服务可以封装独立启动入口。`0.0.0.0` 是监听地址，不能直接当作用户点击网址。对外可达性取决于平台如何把前缀路由到端口，不是传一个 --base-url 就自动配置好了代理。

### 9.2 必须明确的前缀契约

部署时只选择一种代理行为：代理剥离 base_path 后转发，或保留 base_path。服务配置必须匹配，避免双前缀/漏前缀。FastAPI 支持代理环境下的 root_path，转发头只信任受控代理来源。[FastAPI 代理部署说明](https://fastapi.tiangolo.com/advanced/behind-a-proxy/)

前端静态资源、API、media、分享链接都使用同一 BASE_PATH。可通过 index 注入经过 JSON 编码的启动配置；构建采用相对资源路径或与代理匹配的 base。禁止硬写 `fetch('/api/...')` 导致绕过平台前缀，也禁止到处手工拼字符串。采用 query 路由后刷新仍请求同一个入口页面，简化代理回退。

开发可用 Vite dev server + API 代理；正式部署必须使用 build 产物，不能把开发 HMR 端口作为汇报服务。锁定前后端依赖，按项目环境建立独立轻量 Web 环境，避免为了读取结果加载推理依赖、GPU 或下载模型。

### 9.3 发布与回退

先在另一个未占用本地端口验证新服务，现有 asset_viewer 保持运行；检查文档错误恢复、样本结果和媒体 seek。准备好具体服务目录、环境、端口和平台路由后再按实际部署授权切换。不能只停旧服务再发现新页面静态资源 404。

进程管理优先使用服务器已提供的 supervisor/systemd/平台服务机制；容器没有 systemd 时使用平台支持的常驻方式，不假定环境具备 root 服务管理。日志轮转和健康检查独立于模型 pipeline 日志。数据目录只读挂载；cache/log 输出根单独配置。

发布验收包括：本地 healthz、带前缀首页、静态资源、spec、真实列表、视频 Range、音频、刷新/分享链接、未授权 run、软链接允许与拒绝两类路径。回退保留上一前端构建、后端环境及兼容文档快照，不改业务产物。

## 11. 开发顺序与完成标准

### M0：协议和现有运行探测

先实现文档解析器/严格校验和一个运行的 profile 绑定，输出全部模块索引、依赖和内容树；新增 typed errors。用文档二实例作为端到端契约样本，同时覆盖坏 JSON、重复 ID、悬空产物、依赖环、未知协议/adapter。此阶段不接 GPU/模型。

## 12. 验收用例与具体风险

| 场景 | 预期结果 |
|---|---|
| 文档元数据重命名中文标题 | 导航、图节点、结果页标题同步，旧 module URL 保持可用 |
| 文档新增同 renderer/adapter 模块 | 配置校验成功并出现，无前端改码；需正确产物绑定 |

| 文档写到一半/JSON 错误 | 页面不清空，显示尚未生效；首启无旧快照给诊断页 |
| enabled=false / deprecated | 默认导航消失或归档，历史 URL 可解释，不删文件 |
| 运行只有 captions，没有人物产物 | 仍可发现并查看，人物步骤明确未收录 |
| global_0040:S1 与 global_0041:S1 | 是两个实体，筛选/缓存/URL 不串数据 |
| 原片时间与 global-local 时间 | 点击 ASR 9.04 秒正确 seek global 9.04，而非 3521.966083 |
| 新人物对齐 dry-run/skip-model-call | 不显示模型成功归属，不计入确认角色 |
| 物体 status=ok + ambiguous=true | 处理成功但质量有歧义，不出“全部可用”结论 |
| valid 音频与 approved 审核音频 | 按文件/schema 解释，标签与来源均不同 |
| 旧 manifest 绝对路径和允许的软链接 | 通过显式来源绑定可读，provenance 保留原 run |
| 恶意路径/未登记外链/越界软链接 | 不可读取，不能通过 raw preview 绕过 |
| 文件写入中/单行坏 JSON | partial 与具体警告，保留其余/上一稳定结果 |
| 多个同名产物但来源不同 | 报定位歧义，不按搜索顺序随机选择 |

| 带平台前缀刷新和分享 | 页面、静态资源、API、媒体全部走正确前缀 |
